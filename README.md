# ZaprosiVutm

Робот для автоматического списания пива с 1-го регистра ЕГАИС через УТМ.

Windows Forms, .NET Framework 4.7.2, C#. Живёт в трее, раз в сутки запрашивает
остатки у УТМ, отбирает пивные позиции и отправляет акт списания.

> ### ⚠️ Проект не поддерживается
>
> Написан в декабре 2024 года под конкретный магазин и с тех пор не обновлялся.
> Скорее всего, в текущем виде списание уже не проходит: ЕГАИС регулярно меняет
> схемы документов, коды видов продукции и правила работы с регистрами, а код
> здесь прибит к версиям `QueryRests_v2`, `ReplyRests_v2` и `ActWriteOff_v3`.
> Автор это не перепроверял.
>
> Выложено как учебный пример работы с УТМ, а не как готовое решение. Прежде чем
> запускать на живой точке, сверьтесь с актуальной документацией ФСРАР и
> обязательно проверьте результат в личном кабинете.

## Как это работает

```
УТМ (:8080)                     ZaprosiVutm
    |                                |
    |<-- QueryRests_v2 --------------|  запрос остатков 1-го регистра
    |                                |
    |--- ReplyRests_v2 ------------->|  ответ приходит в /opt/out через ~5 мин
    |                                |
    |                                |  фильтр по кодам вида продукции
    |                                |  (пиво, сидр, пуаре, медовуха)
    |                                |
    |<-- ActWriteOff_v3 -------------|  акт списания с причиной "Реализация"
```

1. `Program` ждёт запуска службы УТМ, затем поднимает форму в трее.
2. `EgaisRestWorker.GetCnValueAsync` берёт `FSRAR_ID` из `/diagnosis` самого УТМ —
   в коде он не хранится.
3. `GetTicketForRests` ищет свежий ответ с остатками в `/opt/out`, при отсутствии
   отправляет `QueryRests_v2` и ждёт 5 минут.
4. `ProcessReplyRests` оставляет только позиции с нужными кодами вида продукции.
5. `ProcessProductsToActWriteOff` считает сумму как `цена за литр × ёмкость × количество`
   и собирает `ActWriteOff_v3`.
6. `SendActWriteRequest` отправляет акт обратно в УТМ.

Списываемые коды вида продукции (`500`, `510`, `520`, `261x`, `262`, `263`) заданы
в [`Core/EgaisRestWorker.cs`](Core/EgaisRestWorker.cs). Актуальный список — на сайте
[fsrar.gov.ru](https://fsrar.gov.ru).

## Структура

| Путь | Назначение |
|---|---|
| [`Program.cs`](Program.cs) | Точка входа, ожидание службы УТМ, автообновление |
| [`Core/EgaisRestWorker.cs`](Core/EgaisRestWorker.cs) | Вся работа с ЕГАИС: запросы, разбор и сборка XML |
| [`Core/AppConfig.cs`](Core/AppConfig.cs) | Чтение настроек из `App.config` |
| [`Core/InternetConnectionChecker.cs`](Core/InternetConnectionChecker.cs) | Доступность сервера обновлений |
| [`Core/Logger.cs`](Core/Logger.cs) | Логи в `%AppData%\ZaprosiVutm\Logs\<дата>\log.txt` |
| [`View/MainForm.cs`](View/MainForm.cs) | Форма в трее и сценарий списания |

Рабочие файлы (`ReplyRests_v2.xml`, `ParsedBeer.xml`, `ActWriteOff_v3.xml`) пишутся
в `%AppData%\ZaprosiVutm\UTM\`.

## Настройка

Всё задаётся в [`App.config`](App.config) — в коде адресов нет.

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `UtmHost` | `127.0.0.1` | Адрес УТМ |
| `UtmPort` | `8080` | Порт УТМ |
| `UtmServiceName` | `Transport` | Имя службы УТМ, запуска которой ждём |
| `PricePerLiter` | `100` | Цена за литр для расчёта суммы в акте |
| `UpdateServerLocal` | пусто | Сервер обновлений внутри сети |
| `UpdateServerPublic` | пусто | Он же снаружи |
| `UpdateServerPort` | `4401` | Порт сервера обновлений |
| `LocalProbeHost` | пусто | Хост, по которому определяется локальная сеть |
| `EnableAutostart` | `false` | Прописать себя в автозагрузку |
| `EnableAutoUpdate` | `false` | Качать и ставить обновления |

Если оставить поля сервера пустыми, программа работает автономно и в сеть за
пределы УТМ не ходит.

Нужен .NET Framework 4.7.2 Developer Pack и MSBuild (Visual Studio 2019+).


## Безопасность

Две вещи, о которых стоит знать перед запуском. Обе выключены по умолчанию и
включаются только вручную в `App.config`.

**`EnableAutoUpdate`.** Механизм обновления качает ZIP по обычному HTTP,
распаковывает его и запускает оттуда `.exe`, не проверяя ни подпись, ни хеш. Кто
угодно, кто может подменить трафик или сам сервер, получает выполнение
произвольного кода на машине. Для продакшена это нужно переделывать на HTTPS с
проверкой подписи.

**`EnableAutostart`.** Прописывает программу в
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. В исходной версии это
делалось молча при каждом запуске; теперь требует явного включения.

Ещё стоит иметь в виду: обмен с УТМ идёт по HTTP без аутентификации — так устроен
сам УТМ, он рассчитан на работу с `localhost`. Не выставляйте порт УТМ наружу.

## Что можно доделать

- Получение тикета о результате списания (сейчас акт отправляется «в один конец»).
- Чтение файлов напрямую из папки УТМ вместо HTTP.
- Обработка `EmptyPosition` до сборки документа, а не после.
- Повторные попытки вместо фиксированных пауз в 5 минут.
